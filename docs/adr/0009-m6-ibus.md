# ADR 0009 — M6 IBus engine

## Context

M6 puts prediction into every Linux app via IBus: an engine process that
receives key events + surrounding text from `ibus-daemon`, queries
`predictd`, and renders suggestions as preedit ghost text with a lookup
table. Verified against ibus-daemon 1.5.29-rc2, `zbus` 5.19.

## Decisions

- **Engine binary self-registers** (`RegisterComponent` on startup, payload
  built in `frontend-ibus::component`). Activation needs both the catalog
  entry (`predict.xml` in `/usr/share/ibus/component`) and the live
  registration; the daemon instantiates through our factory
  (`CreateEngine`), so no per-toolkit code exists.
- **Daemon only activates catalog-known component names.** Unknown names
  register `Ok` but stay inert (`Cannot find engine`). Proven by
  activation probes; production is unaffected (our XML installs the name),
  hermetic tests shadow a catalog entry via `PREDICT_COMPONENT_NAME`.
- **IBus wire types carry their leading tag string** (`('IBusText',
  a{sv}, text, attrs)`, …). Our first build omitted tags (self-consistent
  in Rust-to-Rust tests) and the daemon failed closed with
  `bus_engine_proxy_g_signal` criticals. Signature unit tests now pin the
  exact strings, cross-checked against the daemon's registry cache.
- **Never call `message.header()` on daemon-originated traffic.** The
  daemon signs signals with its well-known name; zbus parses sender as a
  unique name and panics. Test pumps dispatch signals by body shape
  (arities are strict).
- **Content-type arrives via `Properties.Set`** (`ContentType =
  (purpose, hints)` on the input context), not a method — confirmed from
  libibus traffic. Password/terminal (8/10) go fully silent.
- **Budgets preserved across the hop**: 10 ms predictd round-trip per key,
  keys always pass through (`ProcessKeyEvent` returns false except Tab
  accept), settled text learned on focus-out.

## Consequences

- Install is system-level (`docs/INSTALL-linux.md`): user component dirs
  are not scanned by this daemon build (syscall-traced).
- Two integration tests: engine-direct (`ibus_engine`) and full client
  path on a private daemon (`ibus_mediated`: activation, ghost, commit,
  password silence, slow-daemon safety).
- GTK/Qt app verification stays manual (no headless toolkits here).
